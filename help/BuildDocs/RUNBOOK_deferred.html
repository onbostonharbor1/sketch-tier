The safety net: pictures before and after

npm run pixels:save -- before takes 25 pictures of the app (every tab, each Commands panel, the Help browser, the Edit Manifest dialog, the Parametrics accordion) into pixel-refs/before/. After a change, npm run pixels:save -- after, then npm run pixels:compare -- before after. It prints identical or DIFFERENT for each picture and puts a red-marked copy of each different one in pixel-refs/diff-after/. Differences of 8 levels out of 255 or less are ignored.

What it cannot see: hover, focus, disabled looks, animation, and any state it does not visit. Each job below says which of those to look at by hand.

Also after every change: npm run lint:globals, npm run check:imports, npm run check:ids, npm run test:node, npm run test:tabs. To undo a job: git checkout claude1 and delete the branch.

Job 2. Show / hide held in state (46 style.display lines)

Goal. Whether a region is shown is a fact in uiState, written when it changes, and one function applies it to the page. No other code sets style.display. This follows your rule: state is written through immediately, and nothing reads the page.

Where each line is. docs/CHECKLIST_sweep-1.md, section 7: the groups, with what each shows or hides and a check for it. Do one group per commit, in this order (lowest risk first): caption.js, categories.js, the two results files, thumbnailWidget.js / textWidget.js, renderer.js, the three canvas-wrapper lines (scriptRunner.js, drawRunner.js, home.js), nextPrevOverlay.js, interactor.js / canvasLayerManager.js, overlay.js and the help/dialog containers, figurePointer.js / figures.js, then figuresNav.js last.

The pattern (copy it for each group).

  1. Add a place in state. In ui/uiState.js, inside the existing state object, add visibility: {} once.
  2. Make one small module, ui/visibility.js: `js import { uiState } from "/ui/uiState.js";

// id of the element, and the display value when it is shown const TARGETS = { captionBar: { id: "caption", shown: "flex" }, figureSidebar: { id: "figure-sidebar", shown: "flex" }, // ... one line per thing that can be hidden };

export function setShown(name, shown) { uiState.visibility[name] = shown; // state first applyVisibility(name); // then the page }

export function applyVisibility(name) { const t = TARGETS[name]; const el = document.getElementById(t.id); if (el) el.style.display = uiState.visibility[name] ? t.shown : "none"; }

export function applyAllVisibility() { // call after a rebuild for (const name of Object.keys(TARGETS)) { if (name in uiState.visibility) applyVisibility(name); } } `

  1. In the file you are converting, replace each el.style.display = "..." with setShown("name", true/false). Add the name to TARGETS. Use the real value that line used ("flex", "block", "grid", ""), as shown.
  2. Where a region is rebuilt (the places clearDivs() empties, or a tab init), call applyAllVisibility() so a rebuilt region gets its state back. This is the step that makes it more than a rename.
  3. ui/regions.js already says what clearDivs() does to the core regions; leave it alone.

Check, for each group. The "Check when converted" column in section 7 of the checklist, then npm run pixels:compare -- before after (should be identical), npm run test:tabs.

Undo. One commit per group, so git revert the one that misbehaves.

A decision to make first. Is #categories / #drawControls (see Job 3) part of this? If they become fixed children, they get entries in TARGETS too. Decide Job 3 first.

Job 3. Fixed #categories and #drawControls in index.html

The situation. index.html is meant to be the one place structure is written. Four things are still created by code: canvas#sharedCanvas (draw/drawState.js), #categories (ui/categories.js), #drawControls (ui/controls/rendering/renderer.js), and the popup menus (ui/menuManager.js). The reason: clearDivs() empties #action, #text and #sketchpad on every tab change, which would delete a fixed child, so code recreates them each time.

The design call. Two ways to make them fixed:

  • Option 1: keep them and empty only their contents. index.html gets <div id="action"><div id="drawControls"></div></div> and <div id="text"><div id="categories"></div></div>. clearDivs() stops emptying #action and #text wholesale; it empties the fixed child, and removes any other children. Price: things other tabs append straight into #action or #text now sit after the fixed child, and an empty fixed child must take no space.
  • Option 2: leave it as it is. Say in index.html that these are content wrappers, not regions (already done). Price: the "one source of truth" is not literally true for these four.

To try Option 1 (about an hour): add the two divs, change clearDivs() and the table in ui/regions.js (add a keep: ["drawControls"] field), change renderer.js and categories.js to find the element instead of creating it (fail loudly if missing, as homeResults.js now does), remove them from the built-by-code list in tests/idCheck.mjs. Then pixels:compare: any DIFFERENT in a tab with a list or sliders means the layout order changed. Check by hand: a tab where both a thumbnail grid and sliders appear (Draw with saved settings), and the Figures strip.

Recommendation. Option 2, unless the pictures come back identical.
