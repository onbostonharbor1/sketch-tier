Review table: main to claude/batch-1

One place for going through every change, in order, with the hand checklists merged in.

How to use it. Work down the tables. Each row has a number in column 1. Quote the number when you want more on an item (for example "N12"). Column 2 says what the change is, with its commit id. Column 3 says what to test or look for.

Number prefixes

PrefixMeaning
GGates and setup (run first, on the PC)
AChanges from main to claude1 (Phases 1 to 8)
PChanges from claude1 to claude/docs (documentation only)
SChanges from claude/docs to claude/sweep-1 (cleanup sweep)
THand tests for the sweep, T1 to T22 (from docs/CHECKLIST_sweep-1.md)
NChanges from claude/sweep-1 to claude/batch-1
BHand tests for the batch, B1 to B16 (from docs/CHECKLIST_batch-1.md)
ZThings to look at last, and things only you can decide

Tags in column 3: ACTION is something you do by hand. CLEANUP is code removed or tidied with no intended change to behaviour; look for breakage nearby. Failure looks like is the sign that the item is broken.

Undo for any commit: git revert <commit>. Commits are listed in column 2 where a row has one. Some items have no commit (documentation rows, and items from merges), and say so.

Automated tests. On this branch, the Linux sandbox passes test:tabs, test:node, lint:globals, check:imports, check:ids, and the import-loop count. The sandbox cannot see Windows, sketchpad.bat, your real files, real printing, or how pictures look. Those are the hand tests below.

Suggested order for a big session (from the batch-1 checklist): G1 to G6 first; then B13 (it fills the pictures the other tabs show); then B1 to B4 and B14; then B5 to B7 and B10; then B3, B12, B15; B8 last. Tell me anything odd.
