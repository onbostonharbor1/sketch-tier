4. What failure looks like, per area

  • Node service: HTTP 403 or 400 and a message naming the field; safe-path rules are in node/safePaths.mjs.
  • Removals: a menu item or tab does nothing, or a red error naming a missing function. All removed names had no callers by search and by check:imports; a dynamic call by string is the one thing a search cannot see.
  • Splits: "does not provide an export named ..." in the browser console.
  • Draw runner move: Draw opens an object but no handles, or it will not redraw when a slider moves.
  • Region table: leftover content after a tab switch, or a region that stays hidden.
  • Side panel / accordion: see T10 and T11.

5. Known things in the result (not bugs introduced here)

  • The main tabs' "active tab" shadow is defined in css/tabs.css but cancelled by a later box-shadow: none !important; the active tab has no shadow today, and did not before. A comment in css/tabs.css says so.
  • parametrics needs #sharedCanvas in the page, so it fails if run before any canvas tab has opened.
  • After the Help button in a Commands panel, both the current tab and Home show as highlighted while the Help browser is open (seen before and after this sweep).
  • voronoi.js (Gallery > Scripts > Generative) loads d3-delaunay from the internet, so it needs a connection even though T14 says the app works offline.
  • window.interactor and window.CanvasManager are tested in a few places but nothing ever sets them (before and after the sweep); the tests are harmless.
  • On a fresh checkout utilities/logfiles does not exist until the first manifest rebuild; Show Logs before then says the folder is missing.
  • #categories, #drawControls and the popup menus are created by code, not written in index.html, because the region they sit in is emptied on each tab change. index.html says so.
