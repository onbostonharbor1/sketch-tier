Checklist: what to check by hand for claude/batch-1 (on top of claude/sweep-1)

Everything here passes the automated tests (test:tabs, test:node, lint, imports, ids). These are the things a test cannot see or that need your PC (Windows, real files, the real Home list). Each says what to do, what a failure looks like, and how to undo. Branch: claude/batch-1. Setup: git fetch, git checkout claude/batch-1, npm install, start as usual. If ui/uiState.js or many files change while Vite is running, stop and restart Vite.

Suggested order for a big session

  1. Set up: git fetch, git checkout claude/batch-1, npm install (Coloris goes away), start the app and the Node service (npm run dev:all or sketchpad.bat). Run npm run lint:globals, npm run test:node and npm run test:tabs once as a baseline (set TEST_LOCAL_BOOTSTRAP=1 only if the CDN is blocked; Bootstrap is gone, so normally not needed).
  2. B13 first (Regenerate thumbnails, Draw then Patterns then Gallery), because it fills the pictures the other tabs show.
  3. B1 to B4 and B14 (quick looks), then B5 to B7 and B10 (figure saving, Home, copy, archive, reset), then B3, B12, B15.
  4. B8 (picture compare) last. Tell me anything odd; small interface differences are fine and need no report.

**B5. Save, Save As, reopen (0b946fc, 3668684). Needs the Node service running (npm run dev:all).**

  1. Figures: new figure, insert two or three objects, weld two corners. Caption menu v > Save As...: the first box asks the category (new name is fine), the second the name. Use a name with a space, such as First try.
  2. In your project folder: figures/<category>/First try.json exists, the category is in figures/directoryRegistry.json, figures/<category>/manifest.json has the entry with status new, help/figures/<category> exists, and no .tmp file.
  3. Menu > Save again: no questions, the file is replaced. Make a change and press Save: the change is in the file.
  4. Menu > Save As... with the same category and name: it says the name exists and asks to replace. Cancel changes nothing.
  5. Try a bad name such as a:b: you get a message and nothing is written (Windows would refuse the name anyway).
  6. Close the figure subtab (the x): with a change since saving it asks; right after saving it does not. Choosing a different layer to look at is not a change. Close it.
  7. Figures > Categories: the category lists your figure. Click it: it opens in a new subtab with the layers, colours, hidden layers, stacking and welds as saved. Drag a handle: a weld still carries the other end. Click it again in the list while it is open: it just shows the open one.
  8. Try a harder one: a figure with a hidden layer, a deleted layer, a changed layer colour, a moved or rotated layer; save, close, reopen; all as left.

Failure: an alert box with a message, a console error, a layer drawn differently after reopening. Undo: git revert 3668684 0b946fc (the saved files stay; delete them by hand).

**B10. Copy, Archive, Reset (be7a108). Needs the Node service for Archive.**

  1. Open a saved figure (B5). Caption menu v > Copy: a new subtab "<name> copy" opens with the same layers; it is unsaved (closing it asks). Changing the copy does not change the original.
  2. In the original, make a change: menu > Reset is now enabled. Reset asks, then the change is gone and the figure is as saved (welds and layers too). Reset is grayed on a figure with no changes or never saved.
  3. Menu > Archive (enabled only on a saved figure): asks; then figures/<category>/archive/<name>.json exists, the original file is gone, the manifest entry is gone, an "Archived" notice shows. The figure stays open and counts as unsaved (closing asks; Save As puts it back).

Failure: Archive leaves the file in place or the entry in the manifest; Reset leaves a drawn layer from the unsaved state. Undo: git revert be7a108 (archived files stay in archive/; move them back by hand).

**B15. Manifest problems in the log, and the Home alert bar (7235fa6).**

  1. Utilities > Commands > Rebuild & Validate. The report now has a "Broken files" list if any manifest entry points at a missing file (or a category folder or manifest is missing). Nothing is changed by the check.
  2. Open the newest file in utilities/logfiles: it starts with PROBLEMS: n and ADDED: n, each followed by its list.
  3. Make a test problem: add an entry to a Patterns manifest.json for a file that does not exist (for example {"filename":"ghost","path":"ghost.js","title":"Ghost"}), then run Rebuild & Validate (or restart with sketchpad.bat: the check runs once at start-up), reload the page and open Home: a yellow bar under the caption says "The last manifest check found 1 problem" and lists it with the log name. Dismiss hides it; it stays hidden for that log, and a later log with problems shows it again. Other tabs never show the bar. Remove the test entry afterward. With the Node service not running the bar simply does not appear.

Failure: no bar although the log lists problems, a bar on other tabs, or a log that does not start with the PROBLEMS summary. Undo: git revert 7235fa6.

B16. Manifest phase: one start-up run, complete rebuild after changes.

  1. Start with sketchpad.bat. The manifest check runs once (not three times). npm run dev alone no longer runs it, and the Node service no longer runs it when it starts.
  2. Entries whose file is gone stay in the manifest and show in the app until you deal with them; the check only reports them (log, and the Home alert bar). Nothing is removed.
  3. After Edit Manifest, Archive, Create Pattern, Create Gallery PNG, or a figure Save, the app does a complete rebuild: it rescans the folders, rewrites every manifest and the combined Home list, drops all in-memory caches and reads them again.
  4. Home status: Patterns > Categories > Edit Manifest on an item, change its status, OK, then click Home. The new status shows without a reload. (The Node service already copied the edit into the Home list; the rebuild also refreshes the app's copy.)
  5. node node/maintain_manifests.mjs from a command line still runs the rebuild by itself.

Failure: Home shows the old status, a missing-file entry disappears, or the check runs more than once at start. Undo: git revert the commit titled "Manifest phase".
