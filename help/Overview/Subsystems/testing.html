Tests and checks

Written 5 November 2026. Every command is run from the project folder; the browser tests need Vite and the Node service running (sketchpad.bat, or npm run dev:all).

CommandWhat it checks
npm run test:tabsThe whole app through a browser: every tab, Figures, welds, print aids, Sweep, stepping, and much more. Extended with every phase.
npm run test:regressionDraws every Draw object, pattern and gallery script and compares each with its approved copy. The report (tests/regression/report.html) shows approved, now, an overlay, a flicker picture and a difference picture for each change. Approve an intended change with -- accept <name>; tests/regression/tolerance.json gives an item its own allowance.
npm run test:errorsThe error bar, the error log, the error checklist, Home > Errors, Checklist, Help and Notes, and the registry and figure-file checks.
npm run test:nodeThe Node service's requests, including lists from the folders.
npm run test:historyScript history.
npm run test:ideabookThe Ideabook Run script button and every hint script.
npm run test:shapersShapers and connectors (no browser).
npm run test:controlsControls by name alone (no browser).
npm run lint:globalsNo undeclared globals: must report 0 errors.
npm run check:imports, check:idsImports resolve; page ids match the region table.
npm run dictionaryWrites docs/FUNCTIONS.md, every function A to Z with the first sentence of its comment.
npm run help:builddocsRemakes Build Documents from docs/.

Hand checks

What tests cannot see (Windows, printing, how a thing feels) is listed on Home > Checklist, one line per check, with details in the phase's docs/CHECKLIST_*.md.

One trap

If a source file is edited while Vite is running, a browser test can end up holding a second copy of the app's state (Vite starts serving the file under a new address). The symptom looks like a real bug. Restart Vite before running the tests after editing code.
