Combinations: two gallery scripts as one drawing

Written 6 November 2026. Code: gallery/Scripts/Combinations/lib/combine.js. Example: framedAlternatingShapes.js (Alternating Shapes inside a Frame). Test and report: npm run test:combinable, which writes gallery/Scripts/Combinations/combinable.md.

A combination is an ordinary gallery script in the Combinations folder. It names two existing gallery scripts and draws both on the canvas as one drawing. The two scripts are imported as they are; nothing in them is changed, and they still run on their own exactly as before. The scripts are not related: no shared points, no welds, and neither reads anything from the other. This is a playpen feature for trying things, not part of the Sketchpad model: no registry object, figure, layer or file format knows about it.

Writing one

import { makeCombination } from "./combine.js";
import { scriptInfo as shapes } from "../Curve Stitch/alternatingShapes.js";
import { scriptInfo as frame }  from "./frame.js";

export const scriptInfo = makeCombination({
  title: "Framed Alternating Shapes",
  first: shapes, firstName: "Shapes",
  second: frame, secondName: "Frame"
});

export function runPattern() {
  scriptInfo.init();
  scriptInfo.redrawHandler();
}

That is the whole file. Save it in the Combinations folder and it appears in the list.

What the combination does

  • Copies. Each script is copied (Object.create with its params cloned, as figure layers copy registry objects), so playing with the combination never changes the script itself.
  • One set of controls at a time. The first control, Controls for, picks whose sliders are in the panel. It is the same grouping that drawing-way selects use (showsGroup and belongsToGroup). Behind the scenes the keys get a prefix (a_color, b_color) so the two scripts' settings stay apart; the scripts never see the prefixes.
  • One set of handles. The first script's points are the handles. The second script has none.
  • Drawing. The canvas is cleared once; then each copy's update and draw run, the first script, then the second. A script's own redrawHandler is never called.

The analyzer: can a script be combined?

checkCombinable(scriptInfo) tries a script the way a combination would and says yes or no, with the reasons. A combination runs it on both its scripts when it starts and refuses, in the red error bar, if either fails. The checks:

  1. It exports scriptInfo with params and a draw(), and its controls have no groups of their own.
  2. A copy draws something without an error.
  3. The copy's draw() does not clear the canvas (that would wipe the first script).
  4. The copy answers its own settings: changing them changes the drawing. A script that says scriptInfo. where it means this. draws from the original and fails here.
  5. The original's settings are the same afterwards (no shared state).

What the first report said

6 of 86 gallery scripts can be combined today. The reasons the others cannot, most common first:

  • 60: draw is a module-level function, not on scriptInfo. These scripts (curveStitch, polygonCorner and most older ones) keep init, update and draw as functions at the top of the file, with their state in module variables. Nothing outside can draw them without editing them. Making one combinable means moving those functions onto scriptInfo and their state onto this: real rewriting, not a mechanical fix.
  • 16: draw() clears the canvas. Mechanical: the clear moves from draw() to redrawHandler.
  • A few single cases: a script with groups of its own, one that will not load, one that needs a canvas id the analyzer's page does not have, one that uses scriptInfo by name.

There is no converter. A converter would edit your gallery scripts, which are yours to change. If the report shows mostly mechanical failures one day, a converter that writes a new file beside the original for you to read is worth building. Today most failures are the first kind, so it would not pay.

Limits

  • Two scripts, named in the file. Choosing them from a list is a possible next step.
  • A script whose controls have their own groups cannot be used yet: its groups would mix with Controls for.
  • The handles are the first script's only.
