The time limit on drawings

Written 6 November 2026. Code: startClock, stopClock and checkClock in draw/drawState.js; called from drawLine, drawActiveTab, the figure redraw and the script runner. Test: npm run test:errors, section 11.

A drawing that runs longer than drawState.timeLimit (2000 ms) is stopped with a message in the red bar, and what it drew so far stays on the canvas, instead of the page freezing.

Why it works from inside

A JavaScript timer cannot interrupt code that is running: a timer only fires when the page is idle, and a drawing stuck in a long loop never lets it be idle. So the check is made by the drawing itself. Every drawing call, drawLine and the canvas's own lineTo, arc, stroke and fill (wrapped once, so scripts that draw on the canvas directly are covered), calls checkClock(). It reads the clock every 256 calls and throws once the deadline has passed. The error is caught where errors are caught already (the Draw redraw, each figure layer, the script runner) and shown in the red bar.

Where the clock runs

  • The Draw tab's redraw: "Draw object <name>".
  • Each figure layer, separately: "Figure "<name>", layer n".
  • A script's runPattern(): "Script <title>".

Limits

A loop that never draws (pure calculation) is not stopped. Animated scripts that keep drawing later, after runPattern() has returned, are not timed. To allow a slow drawing more time, raise drawState.timeLimit (in milliseconds). The regression test runs every object and script; none comes near the limit.
