22.1 Branches, merging and the checklist

Read

CLAUDE.md (How to work with Barry); PHASES.md; home/checklist.md; docs/CHECKING_GUIDE.md.

What happens

Each piece of work is done on a branch, which you review and merge into claude1 (fast-forward, only when you ask). The working branch is deleted afterwards, so only main and claude1 remain. Before merging, you go through the checklist with the guide beside it.

Watch it

Terminal: git log --oneline claude1..claude/tier-a.

Try

Read the commits of one phase and match each to a checklist line.

22.2 How a phase is done

Read

PHASES.md, docs/TIERS.md, any phase's commits.

What happens

Discussion first; building only after your go. The work is done in small, described commits; tests are extended (test:tabs with every phase); the regression test is run before review; docs, help and the checklist are updated in the same branch; anything deferred is listed with the reason.

Watch it

Read docs/TIERS.md sections 5 to 9.

Try

Pick a deferred item and write what it would need.

22.3 Working from the iPad

Read

Help > Design > Subsystems > Running in a Codespace; .devcontainer/.

What happens

A Codespace runs everything in the cloud; Safari shows the app and a browser VS Code. Commit and push work done there; stop the Codespace when finished.

Watch it

Open the repository in a Codespace.

Try

Make a reflection in the Codespace, push it, and see it on the PC.
