Written 6 November 2026 for Sketchpad on branch claude/tier-a. 9.1 index.html, line by line

Read

index.html, all of it, starting at the DIV STRUCTURE comment.

What happens

The comment at the top draws the page as a tree. The body follows it: #wrapper holds the tab row (#mainTabs, one button per tab), then the left column (#button with the Commands button, and the left areas tabs fill), then the main column: #subtabs, #caption, #errorBar, #alertBar, #sketchpad-wrapper with #sketchpad (the canvas host), #text and #action. Outside the wrapper: the side panel (#offcanvasPanel), the overlay container with its help, forms and debug panels, and the Prev/Next overlay. Every id here is used by name in the code.

Watch it

Elements panel (F12): expand #wrapper and match each element to the comment.

Try

Find an id in index.html that the code never uses (check:ids would report it).

9.2 The region table

Read

ui/regions.js; tests/idCheck.mjs (npm run check:ids).

What happens

ui/regions.js lists the regions a tab may fill and clearDivs clears, and the selector for the tab-extra elements of #button. npm run check:ids checks every id in the table really exists in index.html, so the table cannot drift.

Watch it

Terminal: npm run check:ids.

Try

Add a fake id to the table in a copy and run the check.

9.3 clearDivs

Read

ui/uiUtilities.js (clearDivs).

What happens

Called at every tab start: it empties each listed region and removes the tab-extra elements from #button. It is deliberately small: the rule is that teardown stays minimal, because a tab rebuilds what it needs from its own state.

Watch it

Breakpoint in clearDivs; switch tabs.

Try

Find a tab that adds elements to #button and check each carries the tab-extra class.

9.4 Styles

Read

css/ (each file), index.html's links.

What happens

The look comes from a few plain stylesheets: the base styles (which replaced Bootstrap's), the tabs and their themes, the offcanvas and accordion, the controls, the category frames and the help. There is no framework.

Watch it

Elements panel: select a subtab button and read which rules apply.

Try

Change one theme colour in a copy of the CSS and reload.

9.5 Themes per tab

Read

applyTheme in ui/setUI.js; the theme-* rules in css/.

What happens

Each tab has a theme class (theme-home, theme-draw ...) put on #wrapper by applyTheme at the start of a switch; the CSS gives each its colours. That is why the whole page changes colour with the tab.

Watch it

Console: document.getElementById('wrapper').className on two tabs.

Try

Find where the theme name comes from for each tab (the TabSpec's theme).

9.6 The canvas host

Read

ui/draw/drawRunner.js (drawActiveTab moving the canvas), ui/scriptRunner.js (attachCanvasToRegion).

What happens

There is one shared canvas; a tab that draws moves it into #sketchpad and shows #sketchpad-wrapper. A tab that does not draw hides the wrapper. Nothing ever makes a second drawing canvas for the page.

Watch it

Console on Home then Draw: document.getElementById('sketchpad-wrapper').style.display.

Try

Find every place the canvas is appended into a region.

9.7 Canvas layers

Read

ui/canvasLayerManager.js (initCanvasLayers, syncLayerToCanvas); the overlay layers in index.html.

What happens

Above the shared canvas sit transparent canvases for things that are not part of the drawing: the interaction layer (handles), the guides layer. Each is kept the same size and position as the shared canvas, so marks line up. They are cleared and redrawn independently of the drawing.

Watch it

Elements panel: find the layer canvases over #sharedCanvas.

Try

Draw on the interaction layer from the console and see it sit over the drawing.
