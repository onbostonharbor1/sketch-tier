Tutorial 2: Drawing: the core

Written 6 November 2026 for Sketchpad on branch claude/tier-a. Files and functions are named rather than given line numbers, so the text stays right as lines move: in VS Code press Ctrl+P to open a file and Ctrl+Shift+O to jump to a function, or look it up in docs/FUNCTIONS.md. "Watch it" lines use the browser's developer tools (F12): Sources to set a breakpoint, Console to run a line.

Everything Sketchpad draws ends as lines on a canvas, and almost every line goes through one function, drawLine. This tutorial starts at the canvas, reads drawLine closely, and then goes through the building blocks that make the points lines are drawn between: classes, nodes, the old stitchers, the shapers and connectors, curves, intersections and parametric curves.

2.1 The canvas, ctx and the layer canvases

Read

draw/drawState.js: the self-running setup at its end, resetCanvas, and the ctx getter. Then ui/canvasLayerManager.js (initCanvasLayers, syncLayerToCanvas).

What happens

There is one shared drawing canvas (#sharedCanvas), made once when drawState.js loads and kept in window.drawCanvas. Code draws on it through ctx, which is not a plain variable but a getter on window: it hands back the context of the active canvas layer if one is set, else the shared canvas's own context. That is why old code can say ctx.lineTo(...) without importing anything.

On top of the shared canvas sit transparent layer canvases (the interaction layer for handles, the guides layer). syncLayerToCanvas keeps each the same size and position as the shared canvas, so a handle drawn on the interaction layer lands exactly over the line it belongs to. resetCanvas clears the shared canvas to its size in drawState.

Watch it

Console: window.drawCanvas.width, then ctx === window.drawCanvas.getContext('2d') (true when no layer is active).

2.2 drawLine, line by line

Read

drawLine in draw/drawUtilities.js, from its first line to } // end drawLine. Then mapPoint and noteBounds in draw/drawTransform.js.

What happens

Read it in its stages. First the arguments: drawLine accepts a Line object (then colour and width follow) or two points (or two indexes into drawState.pts, turned into points by numbersToPoints). Then the time limit: checkClock() throws once a drawing has run too long (tutorial 17). Then the layer transform: the two ends are noted for the layer's bounds (noteBounds) and mapped through drawState.transform (mapPoint); outside a figure layer both do nothing. Then the print-aid collector: while a figure layer draws, each end is pushed to drawState.collect, which is how a figure without discs can still be printed. Then stepping (tutorial 6): count, record, draw only the first k, mark line k. Then Final mode: if drawState.final is true, only the two end points are drawn as dots. Otherwise the line is stroked with its colour and width, inside ctx.save() and ctx.restore() so nothing leaks.

The rule that every registry object draws only through drawLine is what makes all of these features work everywhere at once.

Watch it

Sources: breakpoint on the first line of drawLine; open Draw > Line; step through one call (F10) and watch pt1 and pt2 change at the transform.

Try

Predict what happens to a figure's printed nails if an object drew one of its lines with ctx.lineTo instead of drawLine. Then check drawState.collect in the code to confirm.

2.3 Point, Line and StringThing

Read

classes/classes.js: class Point, class Line, class StringThing.

What happens

A Point is an x and a y, with helpers (distanceTo, isNear, isSame). A Line has a start and an end and knows its midpoint, its length and how to move (moveMidpointTo, setStart, setEnd). StringThing is the settings bag most older objects carry: colour, line width, number of nodes, ellipse size, scales, midpoint, truncate and shorten, and so on. Objects build one in init() from their params and pass it to the drawing functions as thing.

Watch it

Console: const { Point } = await import('/classes/classes.js'); new Point(0,0).distanceTo(new Point(3,4)) gives 5.

Try

Open drawRegistry/drawLine.js: find where it makes its Line and its StringThing, and where update() keeps params.points in step with the Line.

2.4 Nodes: rings of points

Read

draw/createNodes.js (createNodes).

What happens

Most curve-stitch objects start from a ring of points round an ellipse. createNodes(thing) makes them from the thing's settings: how many nodes, the ellipse's half-widths times the x and y scales, a rotation, a spacing bias (bunching the nodes towards some angles) and jitter (moving them a little at random, by a chosen mode). The nodes are plain Points; what is done with them (spokes, sides, chords) is up to the object.

Watch it

Console, on Draw > Mystic Rose: createNodes is imported by its registry file; set a breakpoint in it and move the Nodes slider.

Try

2.5 The old stitchers

Read

draw/drawUtilities.js: stitcher, drawManyLines, drawLinesAround, drawLinesWithin. draw/drawRegular.js: createArms, changeLine, createParab, drawParab.

What happens

Before November, joining points was done by a few long routines that mixed several jobs: choosing points, reversing, truncating and shortening, wrapping round, and drawing. stitcher(arm1, arm2) pairs two arms point for point. drawRegular.js builds stars and polygons: spokes from the middle (createLinesFromNodesMiddle), sides between nodes (createLinesFromNodesOuter), points along each (createArms, trimmed by changeLine), then stitches pairs of arms.

You found these hard to follow because the cases are tangled together. They still draw the registry objects; the shapers and connectors are the clean replacement for new work.

Watch it

Sources: breakpoint in drawInverseStar (draw/drawRegular.js); open Draw > Inverse Star; step into createParabs.

Try

2.6 Shapers

Read

draw/shapers.js, every function. Tests: tests/shapersConnectors.mjs.

What happens

A shaper takes an array of points and returns a new array; it never changes its input and never draws. linePoints and arcPoints make points; reversed, part, everyNth and rotateStart rearrange them; translated, rotated, scaled and mirrored move them; resampled spaces them evenly along the path; simplified drops points that change nothing; inside, outside and isInside clip to a shape. Every moved point is made by moved(p, x, y), a copy of the old point with only x and y changed, so a Point stays a Point and a z value rides along for later depth work.

Watch it

Terminal: npm run test:shapers and read the test names; each is a small worked example.

Try

In the console, import shapers.js and connectors.js and draw pairwise(part(A, 0, 10), reversed(B)) with drawPairs for two lines of your choosing.

2.7 Connectors

Read

draw/connectors.js, every function; drawPairs in draw/drawUtilities.js.

What happens

A connector takes one or two arrays and returns pairs [a, b]: the lines to draw. pairwise joins i to i (with an offset, wrapping, or spreading the shorter arm across the longer); corner is the classic corner stitch; chords joins i to i + skip; growingChords lets the skip grow; timesTable joins i to i x factor; allPairs joins everything; polyline joins neighbours; mesh joins a grid. A connector knows nothing about reversing or ranges: those are shapers applied first. drawPairs sends each pair through drawLine.

Watch it

Console: const C = await import('/draw/connectors.js'); C.corner({x:100,y:100},{x:100,y:400},{x:400,y:400},10).length gives 11.

Try

Use timesTable on 100 points round a circle with factors 2, 3 and 2.5; say what each draws before drawing it.

2.8 Curves

Read

draw/curves.js, every function, and ring and alongCorners especially.

What happens

Each curve function gives n points of one closed curve, centred and sized. Most use the helper ring, which calls a small formula for each of n evenly spaced angles: the rose is r = cos(k t); the Lissajous figure is x = sin(a t + phase), y = sin(b t); epicycloids and hypocycloids are circles rolling round circles; the superellipse bends a circle towards a square or a star. The rectangle and polygon use alongCorners, which spreads points evenly by distance round a list of corners, so nails fall evenly along the sides.

Watch it

Console: (await import('/draw/curves.js')).rosePoints({x:0,y:0}, 1, 8, {k:2}) and look at the eight points.

Try

Add a new curve formula to a copy of curves.js (for example a figure-eight, x = sin t, y = sin t cos t) and draw its points with polyline.

2.9 Intersections

Read

draw/intersections.js (findIntersections, crossingOf) and Help > Design > Subsystems > Intersections.

What happens

crossingOf is the algebra for one pair of segments: where they cross, and how far along each (0 to 1). findIntersections applies it to whole paths quickly: it builds a grid, notes each segment in the squares its box touches, and tests a segment only against segments already in its squares. A stamp per segment (seenBy) stops a pair sharing several squares from being tested twice. Options set the grid size, which neighbours to skip, end margins, merging of near-duplicates, self or between, closed paths, and limits on count and time.

Watch it

Terminal: npm run test:intersections (watch the 20,000-point timing).

Try

Run it on a figure-eight with closed: true and closed: false, and on two crossing figure-eights with each mode; predict the counts first.

2.10 Parametric curves

Read

classes/parametric.js, then draw/drawParametrics.js: drawParametric, autoFitParametricToCanvas, drawPolar.

What happens

A Parametric holds two functions, x(t) and y(t), and the list of t values to sample. drawParametric first fits the curve to the canvas (measuring its bounds, then scaling and centring it, with the zoom and centre handles applied), then walks the samples drawing a segment each step. The "circuit breaker" stops early when the curve comes back to its start heading the same way, so a closed curve is not drawn twice over. With Show intersections on, the points drawn are handed to findIntersections afterwards and each crossing gets a red dot.

Watch it

Sources: breakpoint at the INTERSECTIONS step near the end of drawParametric; Draw > Parametrics; tick Show Intersection Dots.

Try

Change the circuit breaker's 2-pixel closeness to 20 in a copy and see what a curve looks like when it stops too early.

2.11 Colour and background helpers

Read

draw/color.js (calculateTintAndShade, colourNameToHex), draw/background.js (background).

What happens

Small helpers some scripts use: a lighter and a darker version of a colour, a colour name as its hex code, and a filled background with an optional grid. They draw directly on the canvas (the background is not a line), so the time limit's canvas check applies to them but stepping does not.
