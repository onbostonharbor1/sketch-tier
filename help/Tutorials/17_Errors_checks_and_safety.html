Tutorial 17: Errors, checks and safety

Written 6 November 2026 for Sketchpad on branch claude/tier-a. Files and functions are named rather than given line numbers, so the text stays right as lines move: in VS Code press Ctrl+P to open a file and Ctrl+Shift+O to jump to a function, or look it up in docs/FUNCTIONS.md. "Watch it" lines use the browser's developer tools (F12): Sources to set a breakpoint, Console to run a line.

Errors are caught in a few places only, shown in one bar, written once to a log, and kept as a checklist until ticked. Alongside them sit the start-up and file checks, the time limit and the timing tools.

17.1 Choke points

Read

CLAUDE.md (Errors); drawActiveTab (ui/draw/drawRunner.js), redrawFigure (ui/figures/figureDraw.js), activateWithReport (ui/setUI.js), the file-opening code (ui/figures/figuresSave.js openSavedFigure).

What happens

Errors are caught only where the app can carry on after one: a Draw redraw, each figure layer's draw, a tab switch, opening a file. Each catches, calls reportError(where, err), and goes on (the other layers still draw; the old tab state is kept). Logic elsewhere does not scatter try/catch: an error rises to the nearest choke point.

17.2 reportError

Read

ui/errorReport.js (reportError, reportProblems, placeOf, writeToLog, showBar).

What happens

An error gets a key (where plus message). A new key is shown in the red bar with its file and line (placeOf reads it from the stack) and appended once to utilities/logfiles/errors_<date>.txt; a repeat only counts up in the bar. Uncaught errors and async errors are caught by window handlers installed when the file loads. The file never throws itself.

Watch it

Console: setTimeout(() => { throw new Error("probe") }, 0).

Try

Make the same error three times: read the count in the bar and the single line in the log.

17.3 Ticking, Show all and purging

Read

ui/errorChecklist.js (errorStates, openErrors, acknowledge, purge, readErrorStates); ui/home/homeErrors.js.

What happens

Ticking writes "Acknowledged: <key>" to the log; purging writes "Purged: <key>". errorStates reads every error log in order: an error line opens its key, Acknowledged ticks it, Purged removes it, the same error after a tick opens again. Home > Errors shows the result; the log keeps every line as history.

Watch it

Open a log in VS Code after ticking and purging.

Try

Work errorStates by hand on a five-line example log, then check with the test in tests/errorReport.mjs, section 8.

17.4 Uncaught and async errors

Read

The window "error" and "unhandledrejection" handlers at the end of ui/errorReport.js.

What happens

An error nothing caught (a script's own bug, a failed promise) still reaches the bar, labelled "Uncaught error" or "Uncaught error (in an async step)". A failed image or script load is ignored there.

17.6 The figure-file check

Read

ui/figures/figureModel.js (checkFigureFormat, upgradeFigureV1); Utilities > Tools > Check Figure Files.

What happens

When a figure file is opened, its format, its layers (registry ids that exist, lids, roles), its points and welds, and its drawOrder are checked; problems are reported by name. Older files are upgraded first. Check Figure Files runs the check on every saved figure.

Watch it

17.7 The time limit

Read

draw/drawState.js (startClock, stopClock, checkClock, the canvas wrappers); Help > Design > Subsystems > The time limit on drawings.

What happens

A timer cannot stop running code, so drawings stop themselves: every drawing call checks the clock (drawLine, and the canvas's lineTo, arc, stroke and fill, wrapped once), every 256 calls, and throws once the deadline set at a choke point has passed. The message lands in the bar; what was drawn stays.

17.8 Instrumentation

Read

ui/instrument.js (timed, setInstrumenting, clearTimings, formatTimings); Utilities > Commands.

What happens

timed(label, fn) measures how long something takes when timing is on. Tab switches, list reads and service requests are wrapped. Record timings, then Show timings, lists them: the first place to look when something feels slow.

Watch it

Record timings, switch tabs, open a pattern, Show timings.

Try

Wrap a slow function of your own in timed and see it listed.
