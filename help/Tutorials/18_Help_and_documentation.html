Tutorial 18: Help and documentation

Written 6 November 2026 for Sketchpad on branch claude/tier-a. Files and functions are named rather than given line numbers, so the text stays right as lines move: in VS Code press Ctrl+P to open a file and Ctrl+Shift+O to jump to a function, or look it up in docs/FUNCTIONS.md. "Watch it" lines use the browser's developer tools (F12): Sources to set a breakpoint, Console to run a line.

Sketchpad documents itself in several ways: the Help browser and its editor, Notes from header comments, Home > Help, the build documents, the function dictionary and the checking guide.

18.1 The Help browser

Read

ui/help.js (loadHelpManifest, buildHelpItem), ui/helpTree.js (buildHelpJsTreeData, initHelpJsTree), node/generateHelpManifest.mjs.

What happens

Before Vite starts, generateHelpManifest scans help/ and writes help/manifest.json, a tree of folders and page names. The caption menu's Help opens the browser: a jsTree built from the manifest beside a pane that loads the chosen page's body.

Watch it

Open Help from any caption menu.

Try

Run node node/generateHelpManifest.mjs and read help/manifest.json.

18.2 The help editor

Read

ui/helpEditor.js (openHelpEditorTinyMCE, buildFullHelpHtmlDocument, saveHelpFile); node/writerRequests.mjs (writeHelpFile).

What happens

TinyMCE, a rich-text editor, is loaded only when a page is edited (so starting the app stays quick). Save wraps the edited body in a full page with its title and writes it through writeHelpFile, which only writes inside help/.

Watch it

Edit a reflection (tutorial 18.4).

Try

Find what the editor does on Cancel.

18.3 Notes from header comments

Read

ui/notes.js (extractHeaderNotes); ui/menuCmds.js (makeNotesItem).

What happens

The Notes item shows the comment at the top of a script or object file. Writing a good header is therefore also writing the Notes.

Watch it

Open Notes on a pattern.

Try

Improve one script's header and look at its Notes.

18.4 Home > Help

Read

ui/home/homeHelp.js; node/homeListRequests.mjs (listHelpTopics); Help > Design > Subsystems > Home Help.

What happens

Four groups: Design (help/Overview by subfolder), Reflections (help/Reflections, your topics by title, New reflection and Edit), Build Documents (help/BuildDocs, A to Z) and Tutorials (help/Tutorials, these pages, in order). The lists come from the service, so a new page shows at once.

Watch it

Open each group.

Try

Make a reflection, then find its file.

18.5 Build documents

Read

node/copyBuildDocs.mjs (markdownToHtml, titleOf); npm run help:builddocs; docs/ and docs/old.

What happens

The build documents in docs/ are copied into help/BuildDocs, Markdown converted to HTML by a small converter (headings, paragraphs, lists, tables, code, quotes, rules, bold, italic, code, links and pictures), PDFs shown in a frame. docs/old, the superseded documents, is left out.

Watch it

Run npm run help:builddocs.

Try

Write a Markdown table in a docs file and see it converted.

18.6 The function dictionary

Read

tests/functionDictionary.mjs; docs/FUNCTIONS.md.

What happens

Reads every function declaration in ui/, draw/, classes/, drawRegistry/ and node/, takes the first sentence of the comment above it (or the first comment inside it), and writes the table alphabetically.

Watch it

Run npm run dictionary.

Try

Find the one function listed without a comment, and why.

18.7 The checklist, guide and screenshots

Read

home/checklist.md, docs/CHECKING_GUIDE.md, docs/images/check/.

What happens

The checklist is the list of hand checks (Home > Checklist); the guide is the long form of each check with pictures of correct results; the pictures were taken from the running app by a small Playwright script.

Watch it

Open the guide in Build Documents beside the checklist.

Try

Add a check of your own with Add item.
