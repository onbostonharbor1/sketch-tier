1.1 What Sketchpad is for

Read

CLAUDE.md, the section "What Sketchpad is for". Then docs/TIERS.md, section 2, for what was added in November 2026.

What happens

Sketchpad has two purposes, and the code serves both. The first is a printable, true-size template for driving nails: that is why figures have discs, welds, units, print sizes, spacing checks and the one-sheet SVG. The second is a place to sketch: to try ideas cheaply. That is why there are sliders on everything, handles you can drag, Sweep, stepping, and objects such as Circular Parabola (Multi) and Linked Circles that exist because they are interesting.

When you read any part of the code, ask which purpose it serves. Most of the Figures code serves the first; most of the Draw tab and the controls serve the second; the drawing core serves both.

Watch it

No code: open the app and, for each tab, say aloud which purpose it serves.

Try

Find one feature that serves both purposes equally (stepping is a good candidate: it finds errors in a template and it shows how a design is built).

1.2 The page: fixed regions

Read

index.html, from the DIV STRUCTURE comment to the end of the body. Then ui/regions.js and ui/uiUtilities.js (clearDivs).

What happens

The page never builds its main areas on the fly. index.html declares them once: the tab row (#mainTabs), the left column (#button, holding the Commands button), the subtab row (#subtabs), the caption (#caption), the canvas area (#sketchpad), the text area (#text), the controls area (#action), the error bar (#errorBar), the Home alert bar (#alertBar), the side panel (#offcanvasPanel) and the overlays.

When a tab is shown, clearDivs() empties every region the region table lists, and the tab fills in what it needs. #button itself is never emptied, because the Commands button lives there; anything a tab adds to it carries the class tab-extra, and clearDivs() removes just those. This is the "no ad hoc divs" rule: content goes into fixed regions, never into new top-level divs.

Watch it

Console: document.querySelectorAll('#button .tab-extra').length on the Figures tab (several), then on Home (0).

Try

Read clearDivs and list every region it clears. Compare with the regions in index.html: which one is never cleared, and why?

1.3 Start-up, step by step

Read

main.js (top to bottom), then onDomContentLoaded in ui/setUI.js.

What happens

main.js is a list of imports. Their order is the start-up order: the error reporter first (so anything that fails later is reported), then the classes, then drawState (which makes the shared canvas and the ctx getter) and the drawing files, then every registry file (each puts its object on window as drawRegistry_<name>), then drawRegistry.js, which gathers them into window.drawRegistry. Near the end, main.js runs the registry check (checkDrawRegistry, ui/registryCheck.js) and reports any fault to the red bar.

When the page has loaded, onDomContentLoaded (ui/setUI.js) runs: it starts the menu manager, the overlays and the canvas layers, wires the six tab buttons to handleTabChange, and calls setUI("START_APP"), which shows Home. Tab state is not kept across a reload: every tab starts fresh.

Watch it

Sources: open ui/setUI.js, set a breakpoint on the first line of onDomContentLoaded, reload, then step over each line (F10).

Try

Add a deliberate mistake to a copy of a registry object (for instance remove its draw), reload, and see the start-up check report it. Undo afterwards.

1.4 The two state objects

Read

ui/uiState.js (all of it) and the drawState object at the top of draw/drawState.js.

What happens

Barry's rule: no implicit globals. Any value shared across files is declared in one of two objects. uiState holds the interface: which tab is active, each tab's open subtabs and remembered views, the launch request between tabs, the Home and Figures settings, thumbnails, instrumentation. drawState holds the drawing: canvas size, Final mode, the layer transform and bounds, the print-aid collector, stepping, and the time limit.

Because each value has one home, you can always find who reads and writes it with a search for its name. Tutorial 19 goes through both objects field by field.

Watch it

Console: uiState (it is also on window, for debugging) and expand it; then (await import('/draw/drawState.js')).drawState.

Try

Search the code for uiState.figures.hitRadius: where is it declared, who reads it, who changes it?

1.5 Folders: what lives where

Read

The top of the repository in VS Code's Explorer. Then CLAUDE.md, "Architecture in brief".

What happens

ui/ is the interface: tabs (ui/home, ui/draw, ui/patterns, ui/gallery, ui/utilities, ui/figures), controls (ui/controls), and the shared pieces (setUI, categories, caption, menus, overlays, errors). draw/ is the drawing: drawLine and its helpers, nodes, stitching, shapers, connectors, curves, intersections, parametrics, transforms, drawState. classes/ holds Point, Line, StringThing and Parametric. drawRegistry/ holds one file per Draw object. node/ is the local service.

The libraries are folders of your own content: patterns/, gallery/ (Ideabook, Patterns, Scripts), utilities/ (Tools, Lab), figures/. help/ is the help (Overview, Reflections, BuildDocs, Tutorials); docs/ the build documents; tests/ the tests; home/ holds Home's notes and checklist.

None needed.

1.6 Reading a file

Read

Any file, for example draw/connectors.js. Then docs/FUNCTIONS.md, and tests/functionDictionary.mjs.

What happens

Every source file starts with a header comment saying what it does; the Notes popup shows the header of scripts. Every function has a comment just above it (since the November comment sweep). npm run dictionary gathers the first sentence of each into docs/FUNCTIONS.md, alphabetically, with the file and line. When you meet an unfamiliar name, look it up there first; Ctrl+click in VS Code then takes you to it.

Watch it

Terminal: npm run dictionary, then open docs/FUNCTIONS.md and search for drawLine.

Try

Pick three functions in docs/FUNCTIONS.md whose one-line summary you find unclear, read the functions, and write a better sentence (then tell me, or change the comment yourself).
