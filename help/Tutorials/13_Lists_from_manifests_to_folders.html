Tutorial 13: Lists: from manifests to folders

Written 6 November 2026 for Sketchpad on branch claude/tier-a. Files and functions are named rather than given line numbers, so the text stays right as lines move: in VS Code press Ctrl+P to open a file and Ctrl+Shift+O to jump to a function, or look it up in docs/FUNCTIONS.md. "Watch it" lines use the browser's developer tools (F12): Sources to set a breakpoint, Console to run a line.

Every list in Sketchpad (the categories of Patterns, Gallery, Utilities, Figures and Draw's saved settings, and Home's statuses) used to come from manifest.json files. Since 4 November they come from the folders themselves. This tutorial tells the story, reads the new code, and traces a file from saving to appearing.

13.1 The history: why manifests were fragile

Read

docs/old/ (the batch-1 documents), help/Overview/Subsystems/manifest.html, node/maintain_manifests.mjs.

What happens

Each category folder had a manifest.json listing its items, and each library a directoryRegistry.json listing its categories. A list was only as right as its manifest: a script saved in VS Code did not appear until the manifest was edited or rebuilt; an entry whose file had gone broke the list; a start-up rebuild (maintain_manifests.mjs, run by sketchpad.bat) tried to keep them in step and stopped start-up when it failed; and Home's list (home/manifest.json) had to be rebuilt from all the others after every edit.

13.2 libraryIndex, line by line

Read

node/libraryIndex.mjs: LIBRARIES, categoriesOf, itemsOf, listLibrary.

What happens

LIBRARIES names the eight libraries and the kind of file that is an item in each (scripts .js; pictures for the Ideabook and gallery Patterns; .json for figures and saved settings). categoriesOf reads the folders: directoryRegistry.json's order first, then any other folder, A to Z, skipping images, scripts, archive and hidden folders. itemsOf reads a folder's files of the right kind (thumbnails and list files excepted), then takes the manifest's entries as notes: an entry whose file is gone is dropped; files with no entry come after, titled by their file name. listLibrary puts it together, leaving out a folder not in the registry that holds no items.

Watch it

Terminal: node -e 'import("./node/libraryIndex.mjs").then(async m => console.log((await m.listLibrary({basedir:"patterns"})).categories))'.

Try

Make a scratch folder in patterns/ with one .js file; run the line above again.

13.3 The two requests

Read

listLibrary and listHomeItems in node/libraryIndex.mjs; the dispatcher in node/sketchpadService.mjs.

What happens

listLibrary { basedir } answers { categories, items }, where items[i] belongs to categories[i], each entry { filename, path, title, ...notes }: exactly the shape the page always read from manifests, so no tab changed. listHomeItems walks the libraries the same way and returns every item that has a status, sorted by title.

Watch it

Console: (await import('/ui/nodeLayer.js')).nodeDispatch('listLibrary', { basedir: 'utilities/Tools' }).

Try

Compare the answer with utilities/Tools' folders and manifests.

13.4 ManifestManager on the page

Read

ui/manifest.js: get, loadOrCache, getCategoryMap, register, invalidate, clearCache.

What happens

Tabs ask manifest.get(basedir). For the eight libraries it asks the service for listLibrary and keeps the answer in its cache, with the category names in its registry cache. getCategoryMap gives { category: [entries] }. invalidate(key) forgets one library and calls the tabs registered for it; clearCache forgets all.

Watch it

Breakpoint in loadOrCache; open Patterns.

Try

Find which tab registers a refresh callback, and what it does.

13.5 The fallback

Read

loadOrCache in ui/manifest.js, after the listLibrary attempt.

What happens

Without the service (a read-only copy of Sketchpad), the request fails and the old path runs: directoryRegistry.json and the manifest files are read directly. So the manifests still matter for a copy with no service.

Watch it

Stop the Node service, reload, open Patterns: still listed (from manifests).

Try

Find the check that treats an answer without lists as a failure.

13.6 What still writes manifests

Read

node/manifestRequests.mjs (editManifestEntry, archiveItem), node/figureFiles.mjs, node/writerRequests.mjs, node/thumbnailRequests.mjs.

What happens

Edit Manifest writes a title or status into an entry; Archive moves a file and removes its entry; saving a figure, Create Pattern and Create Gallery PNG add entries; thumbnail tools note pictures. All of this is now notes: if it went wrong, the item would still appear, just with its file name as title.

13.8 Archive

Read

ui/archiveItem.js; node/manifestRequests.mjs (archiveItem).

What happens

Archive moves the item's file into the category's archive folder and takes it out of the manifest, then the lists are read again. Archive folders are skipped by the index, so the item leaves its list.

13.11 A file from saving to appearing

Read

All of the above.

What happens

Save patterns/circles/new.js in VS Code. Nothing happens yet: there is no file watcher (Node's is unreliable on Windows). Reload the page (or Rebuild): Patterns asks manifest.get("patterns"), which asks the service, which reads the folder and finds new.js with no manifest entry, so it lists it after the others, titled new.js. categories.js draws it.

Watch it

Breakpoints in loadOrCache and the service's itemsOf (the Node terminal shows nothing; use console.log in a copy).

Try

Time how long from saving to seeing it.

13.12 How it was proven

Read

The commit message of the lists change (git log --grep "Lists from the folders"); tests/nodeSmoke.mjs, the listLibrary block.

What happens

Before switching, every library's new lists were compared item by item with the manifests: identical. The service test builds a scratch library and checks the order, the notes, a file with no entry, an entry with no file, a folder with only pictures, and refusal of a folder outside the libraries.

Watch it

Terminal: npm run test:node.
