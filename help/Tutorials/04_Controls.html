The sliders, pickers and lists beside every drawing are built from each object's controls description. This tutorial follows a control from its description to the screen, through each kind of widget, the two grouping systems, controls by name alone, and what happens when you move one.

4.1 From description to screen

Read

ui/controls/controlsCore.js (buildParameterControls), ui/controls/builders/dataBuilder.js (buildDrawParameterData, buildScriptParameterData), ui/controls/rendering/renderer.js (renderParameterControls).

What happens

buildParameterControls(info, tabId, render) decides where the controls come from: a Draw object (info.drawRegistry) or a script (info.controls). A data builder turns each entry into a plain item: key, label, widget, min, max, step, options and the current value (from info.parameters, else the default). The group filter (4.3) drops items that should be hidden. The renderer then builds each item's widget (buildSingleControl) into #action, or into the interface area for controls marked as interface controls.

Sources: breakpoint in buildDrawParameterData; open any Draw object; look at the items array it returns.

4.2 Each widget

Read

ui/controls/widgets/: rangeWidget.js (setRangeControl, setRangeControlUnified), checkboxWidget.js, colorWidget.js, selectWidget.js, radioWidget.js, textWidget.js (setDefaultControl), accordionWidget.js, thumbnailWidget.js.

What happens

Each widget function gets the field, the label, the description, the current value, the info object, the key and the tab id, and builds one control. Sliders show their minimum, maximum and value, keep values in range (clampValue) and write the value (applyValue). Checkboxes, colour pickers, lists and radio buttons write their value on change. The text box is the fallback. The accordion holds sections of buttons; the thumbnail grid offers pictures to choose from.

4.3 Showing and hiding controls (control groups)

Read

ui/controls/builders/groupFilter.js (filterControlsByActiveGroups), Help > Design > Subsystems > Control Grouping System.

What happens

A select can declare showsGroup: true; other controls declare belongsToGroup: "name". Only the controls belonging to the group the select currently names are shown (plus any with no group). Changing such a select rebuilds the controls. Used by objects whose settings depend on a mode.

Watch it

Open an object with a mode select (In Ellipse or Linked Circles) and change the mode.

Try

Add a group to a copy of a script's controls and watch controls appear and disappear.

4.4 Controls by name alone

Read

ui/controls/builders/conventions.js (CONVENTIONS, GROUPS, expandSchema); tests/controlConventions.mjs.

What happens

A control declared by name only (lineWidth: true) is filled from the conventions table: widget, label, range, step and default. One change keeps the rest ({ lineWidth: { max: 3 } }). A group stands for several: { style: "group" } becomes colour, line width and transparency. Anything written in full is untouched. expandSchema is applied by the data builders, the group filter and the renderer, so all three see the same filled-in description.

Watch it

Terminal: npm run test:controls.

Try

Write a tiny script with controls: { style: "group", steps: true } and run it in Utilities > Lab.

4.5 When a control changes

Read

The applyValue functions in rangeWidget.js; onParamChange and redrawHandler set in ui/draw/drawRunner.js (drawActiveTab); figures: ui/figures/figureLayerPanel.js.

What happens

A widget writes the new value into info.parameters (which for a Draw object is the object's params), calls info.onParamChange (Draw marks the subtab as changed), and calls info.redrawHandler, which for the Draw tab is drawActiveTab: update() then draw(). Nothing is saved separately: the value is already where it lives ("written through immediately").

Sources: breakpoint in a slider's applyValue; move it; step until drawActiveTab.
